## Бенчмарки: как заполнять

Таблица для заполнения — **`benchmarks.csv`** (90 строк: 10 клиентов × 3 источника × 3 сегмента).
Разделитель `;`, кодировка UTF-8 с BOM — русский Excel открывает двойным кликом,
в Google Sheets: Файл → Импорт → выбрать файл (разделитель определится сам).

Колонки для заполнения: `показы`, `уникальные пользователи`, `клики`, `cpm`, `ctr`, `cpc`.
Формат свободный — как пишешь, так и попадёт в слайд (например `94 075`, `224 ₽`, `0,63%`).
Пустая ячейка остаётся в презентации как «после сбора» (новые клиенты 08.09 — Отисифарм, Paygine, ИРИС-М — пока без бенчмарков). Можно заполнять частями.

Колонки `client_key`, `source`, `segment` не менять — по ним строки находят свои таблицы.

После заполнения:

```bash
python3 generate.py
```

— цифры подставятся в таблицы бенчмарков всех презентаций. Или просто закоммить CSV — перегенерирую.

## Публикация

GitHub Pages собирается из ветки `gh-pages`, а не из `main`. После коммита в `main`:

```bash
git push origin main && git push origin main:gh-pages
```

Без второй команды сайт omenikarch.github.io/Preliminary_audit остаётся на старой версии.

## Как обновлять контент

Контент клиентов — в `clients_data.py` (сегменты, цифры ниш, lift-данные, рессейлинг).
После правки — тот же `python3 generate.py`.

## Структура каждого аудита (22 слайда)

1. Титул → 2. Резюме встречи (ответы клиента + диагноз) → 3. Ниша в цифрах →
4. Согласование проекта → 5–7. Ozon (таргетинги, сегменты, бенчмарки) →
8–10. Яндекс Urban Ads (форматы, сегменты, бенчмарки) → 11–12. WB Media (сегменты, бенчмарки) →
13. Сравнение источников → 14–16. Замеры (Search/Brand/Sales lift, Post-view: бенчмарки + план) →
17–18. Рессейлинг (13 кабинетов + каналы под нишу) → 19. Готовность сайта →
20. Условия → 21. Рекомендации → 22. Следующий шаг.
